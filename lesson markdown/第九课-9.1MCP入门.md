# 第九课 · 9.1：用 MCP 调用计算器

这一课把已有的贴现计算器放到一个独立的 Python 进程里，再通过 MCP 调用它。先跑通连接，下一节再接回 Qwen 和 LangGraph。

**MCP 是程序之间发现、调用工具的通信协议。** 它不负责计算，也不替模型决定用哪个工具。

## 1. 先分清三个角色

| 名称 | 本课中是谁 | 做什么 |
| --- | --- | --- |
| Host（宿主程序） | `lesson09a.py` 这个程序 | 读取命令行参数，安排调用和显示结果 |
| Client（客户端） | 宿主程序里的 MCP 连接部分 | 与 Server 握手、获取工具列表、发送调用请求 |
| Server（服务端） | `lesson09a_server.py` 独立进程 | 告诉客户端有哪些工具，并执行收到的工具调用 |

Skill 提供工作方法；Tool 提供实际功能；MCP 规定这些工具怎样被另一个程序发现和调用。

本课不调用 Qwen、Redis 或 RAG，不需要启动 Redis，也不产生模型调用费用。

本课锁定官方 Python SDK `mcp==2.3.0`，服务端类名为 `MCPServer`。依赖更新只增加 MCP 所需包，安装器会先备份原来的依赖文件。

## 3. 发现工具，再调用工具

先看服务端提供什么：

```powershell
uv run python lesson09a.py --list-tools
```

你会看到计算器的名称、描述和参数 schema。schema 相当于参数说明书：这个工具需要哪些参数，以及参数是什么类型。

然后计算默认例题，再改天数：

```powershell
uv run python lesson09a.py
uv run python lesson09a.py --days 180
```

默认参数为票面金额 10000 元、年贴现率 3%、90 天，按一年 360 天计算，结果应为 **75.00 元**。改成 180 天后，应为 **150.00 元**。

此时参数来自命令行，工具调用由 Python 程序安排，**还没有模型参与选择**。客户端收到的是带字段的结构化结果，再把它显示出来。

## 4. 这条命令背后发生了什么

```text
启动 Server 子进程 → initialize 握手 → list_tools 发现工具
                                      ↓
                           call_tool 发送名称和参数
                                      ↓
                           Server 计算 → 返回结果
```

`initialize` 用于建立 MCP 会话并交换协议和能力信息；`list_tools` 只取得工具说明；只有 `call_tool` 才会请求执行计算。

本课使用 `stdio`，通过子进程的标准输入、标准输出交换消息。Server 的 **stdout 专供 MCP 协议使用**，调试信息应写到 stderr，随意 `print()` 到 stdout 可能破坏通信。

直接运行 `lesson09a_server.py` 时，它会等待客户端输入，看起来没输出是正常的。平时运行客户端即可，它会启动 Server；退出客户端的上下文管理块后，会清理服务子进程。

MCP 也支持通过 HTTP 连接远程服务，本课先用本机进程理解流程，远程连接留到后续。

读代码时，先看 `lesson09a_server.py` 怎样注册计算器，再看 `lesson09a.py` 怎样依次调用 `initialize()`、`list_tools()` 和 `call_tool()`。下一节再让 Qwen 决定何时通过 MCP 调用它。
