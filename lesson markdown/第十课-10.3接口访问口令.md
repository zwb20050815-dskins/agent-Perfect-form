# 第十课 · 10.3：给问答接口加访问口令

这节增加一个规则：**请求先通过口令检查，才能提问或读取历史。** 检索、Skill、MCP 和 Redis 继续沿用，不需要重建笔记向量。

本节先在自己的电脑上练习。宝塔是管理服务器的面板；后续需要确认它实际安装在哪台主机上，再安排部署。

## 1. 两种密钥，各管一段

| 名称 | 谁拿它访问谁 |
| --- | --- |
| 本节的访问口令 | 调用者 → 你的知识 Agent |
| 原来的 Qwen API Key | 你的知识 Agent → 云端模型服务 |

两者分开保存：原来的配置在 `.env`，本节口令在 `.env.access`。

```text
请求 → 检查访问口令 → Agent 处理 → 返回回答
              └─ 缺少或不正确 → 返回 401
```

`401` 表示这次请求没有通过身份验证，此时不会开始检索或调用云端模型。

## 2. 安装并生成口令

在 PowerShell 执行：

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
uv run python 'C:\Users\Zwb\Documents\Codex\2026-10-06\n-h-2\outputs\knowledge-agent\install_lesson10c.py'
uv run python lesson10c.py --init-token
```

这节没有新增依赖。最后一条命令会在本机生成 `.env.access`，其中包含随机的 `AGENT_ACCESS_TOKEN`；已有文件不会被覆盖，口令也不会打印到终端。

打开文件，复制 `AGENT_ACCESS_TOKEN=` **等号后面的内容**，稍后填入测试页面：

```powershell
notepad .env.access
```

口令只在你自己的电脑上使用，不需要发给我。

## 3. 启动接口

先打开 Docker Desktop，等引擎运行，再启动原来的 Redis：

```powershell
docker compose -f compose.redis.yaml up -d --wait
uv run python lesson10c.py
```

保持这个窗口开着，打开 [本机接口测试页面](http://127.0.0.1:8000/docs)。这次先用 Windows 上的 Python 运行接口，地址仍然是本机的 `8000` 端口。

## 4. 对比未授权和已授权

先不要点击 **Authorize**。展开 `POST /chat`，点击 **Try it out**，填入：

```json
{
  "session_id": "access-study",
  "question": "票面金额10000元、年贴现率3%、剩余90天，按一年360天计算贴现利息。"
}
```

点击 **Execute**，应得到 **401**。这说明问答请求被口令检查拦住了。

接着点击页面顶部的 **Authorize**，粘贴刚才复制的口令，确认授权后关闭弹窗。**只填口令本身，不用手写 `Bearer`。** 页面会自动把它放进请求头。

再次执行相同请求，应得到 **200**，回答中的贴现利息应为 **75.00 元**。

展开 `GET /sessions/{session_id}/history`，填入 `access-study` 并执行，也能读到历史。点击 **Authorize → Logout** 取消授权后，再读历史应得到 **401**。

`/health`、`/docs` 和 `/openapi.json` 可以直接访问，分别用于健康检查、测试页面和接口说明；它们不会直接返回会话历史。

## 5. 口令与会话编号的区别

**访问口令决定能否使用接口；`session_id` 决定使用哪段历史。** 只知道会话编号，不能绕过口令检查。

本节是个人使用的单口令方案：持有同一个有效口令的人，可以访问这个 Agent 的各个会话。它还没有为多人分别分配账号和历史权限。

看代码时先找 `lesson10c.py` 中的两个函数：

- `read_token()`：读取本机保存的访问口令。
- `require_access()`：检查请求带来的口令，失败时返回 401。

已有 API 的 `create_app()` 接受这个检查函数，将它应用到提问和历史接口；Agent 本身的检索与工具流程不用重写。

## 6. 可选：让容器版也使用口令

完成上面的本机练习后，在另一个 PowerShell 窗口进入项目，执行：

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
docker compose -f compose.redis.yaml -f compose.api.yaml -f compose.access.yaml up -d --build --wait --wait-timeout 180
```

它会把原来 `8001` 端口的 API 替换为本节版本，沿用 Redis 和数据卷。打开 [容器版测试页面](http://127.0.0.1:8001/docs)，使用同样的口令测试。

`.env.access` 通过只读挂载交给容器，不会打包进镜像。今后操作这个带口令的容器版时，Compose 命令都要带上这三份文件。例如停止 API：

```powershell
docker compose -f compose.redis.yaml -f compose.api.yaml -f compose.access.yaml stop api
```

如果只用上一节的两份文件重新启动 API，会恢复到上一节没有口令检查的版本。
