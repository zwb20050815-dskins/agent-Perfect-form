# 第六课 · 6.2：退出程序后，用 Redis 接着聊

这一节保留 6.1 的对话流程，把保存器换成 `RedisSaver`。Python 退出后，下一次运行仍能恢复同一会话。

**沿用现有的 Qwen3、Embedding 和 Rerank 配置，不需要更换模型或密钥。**

## 1. 安装并启动 Redis

先打开 Docker Desktop，等它启动完成，再在 PowerShell 中依次执行：

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
uv run python 'C:\Users\Zwb\Documents\Codex\2026-10-06\n-h-2\outputs\knowledge-agent\install_lesson06b.py'
uv sync --locked
docker compose -f compose.redis.yaml up -d --wait
uv run python lesson06b.py --check
uv run python lesson06b.py --check-redis
```

`uv sync --locked` 按锁定版本安装依赖。Compose 启动 Redis 8.2；本机端口是 **6380**，容器内部端口是 **6379**。未设置 `REDIS_URL` 时，程序默认连接 `redis://127.0.0.1:6380/0`。

`--check` 检查本地配置与索引，不连接 Redis 或模型；`--check-redis` 连接 Redis 并初始化检查点索引，不调用模型。看到初始化通过后，再开始提问。

## 2. 同一个会话，换一个 Python 进程

先执行第一条提问命令。把问题写在命令后面，程序回答完成后会自动退出，回到 PowerShell 提示符：

```powershell
uv run python lesson06b.py --session study "试算平衡能发现所有记账错误吗？"
```

然后执行下面这条。它启动的是**新的 Python 进程**，但仍使用 `study` 会话：

```powershell
uv run python lesson06b.py --session study "那它查不出来哪些错误？"
```

如果 `study` 此前没有记录，第二次应显示可用历史为 1 轮，并把追问补成完整的检索问题。观察“本轮检索问题”，检查模型有没有理解“它”指什么。

这次仍会重新检索笔记、重排和生成回答；回答中的引用来自本轮找到的资料。

退出后也能单独查看历史，这条命令不调用模型：

```powershell
uv run python lesson06b.py --session study --history
```

还可以重启 Redis，再查看同一份历史：

```powershell
docker compose -f compose.redis.yaml restart redis
uv run python lesson06b.py --session study --history
```

等 Redis 重启完成再查；记录仍在，说明它也能从磁盘恢复。

## 3. 换一个会话编号

```powershell
uv run python lesson06b.py --session other --history
uv run python lesson06b.py --session study
```

`other` 如果从未使用过，历史应为 0 轮。第二条命令进入连续对话，依次输入：

```text
/session other
/history
/session study
/history
/quit
```

切回 `study` 后能看到它自己的记录。`/quit` 只退出 Python，不清空 Redis。会话编号可以自己起；相同 Redis、相同项目前缀和相同编号，才对应同一份记录。

## 4. 谁负责保存什么

| 名称 | 本课的作用 |
| --- | --- |
| `State` | 流程当前的数据，包括问题、资料、答案和 `history` |
| `RedisSaver` | 把 State 等流程状态保存为检查点，并按会话恢复 |
| Redis | 独立运行的数据库，Python 退出后仍能保存这些记录 |
| AOF | Redis 的磁盘日志，用于 Redis 重启后恢复数据；本课设置 `appendfsync always` |
| Docker volume | 保存 Redis 的 `/data` 目录，让数据独立于容器存在 |

数据卷名称是 `knowledge-agent-memory-redis-data`。平时暂停服务可以执行 `docker compose -f compose.redis.yaml stop`，再用前面的 `up` 命令启动；**不要把带 `-v` 的删除命令当作日常停止操作。**

`durability="sync"` 表示 LangGraph 等待本步检查点写入完成，再继续下一步。它本身不是磁盘持久化保证；Redis 如何写盘由 AOF 等设置负责，数据卷也不能替代备份。

模型没有自动获得永久记忆。程序恢复 State 后，把需要的近期历史重新交给模型，帮助它理解追问。

## 5. 代码与边界

打开 `E:\agent Perfect form\knowledge-agent\lesson06b.py`，先看三处：

1. `open_redis_graph()`：连接 Redis、初始化索引，再把保存器传给沿用的 `build_graph()`。
2. `session_config()`：为编号加上 `knowledge-agent:lesson06b:v1:` 前缀，提问和查看历史都使用它。
3. `invoke_turn()`：提供本轮输入并清空临时结果，保留恢复的历史，使用同步保存。

- **6.1 的内存记录不会自动迁移。** 6.2 从 Redis 中已有的记录开始，没有记录就是新会话。
- **知识库向量仍在 `E:\agent Perfect form\knowledge-agent\data\vectors`。** 本节只接入会话保存，没有把向量检索改到 Redis。
- **问题补全模型只接收最近 3 轮完成的问答。** 更早的检查点可能仍在 Redis；这不表示旧数据已经删除。历史中的引用编号也只属于原来那一轮。
- **Redis 出错时不会退回内存保存。** 恢复连接后先用 `/history` 核对已保存记录，再继续提问；报错不代表所有写入都没有发生。

换一个项目目录也不会自动得到新的会话空间：这份配置使用固定的数据卷名和会话前缀。
