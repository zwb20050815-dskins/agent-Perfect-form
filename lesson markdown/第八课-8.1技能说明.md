# 第八课 · 8.1：用 Skill 说明工作方法

这一节让同一个 Agent 按不同的工作方法回答：**Skill 说明怎么做，Tool 执行具体操作，RAG 提供知识依据。**

本课的 `skills` 位于你的 `knowledge-agent` 项目内，由自己的 Python 程序加载；它不是安装到 Codex 全局的技能。本课继续使用 7.2 的工具、笔记向量、Redis 配置和会话流程。

## 1. 安装并查看技能

在 PowerShell 执行：

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
uv run python 'C:\Users\Zwb\Documents\Codex\2026-10-06\n-h-2\outputs\knowledge-agent\install_lesson08a.py'
uv run python lesson08a.py --list-skills
uv run python lesson08a.py --skill bank-study --show-skill
```

`--list-skills` 列出名称和描述，供你选择；`--show-skill` 显示选中技能的正文。两者都不联网。本课由你用 `--skill` 选择，尚未实现模型自动选择技能。

打开 `skills/bank-study/SKILL.md`，顶部两行 `---` 之间是元信息：`name` 是技能名，必须与目录名一致；`description` 简述用途。后面的 Markdown 正文是具体工作方法。

`bank-study` 要求解释加计算时，尽量按“白话解释 → 计算结果 → 条件提醒”组织回答。知识仍来自本轮 `search_notes`，数字仍来自计算器；**技能说明本身不是知识来源**。

## 2. 用同一道题做对照

先检查本地文件和 Redis：

```powershell
uv run python lesson08a.py --check
uv run python lesson08a.py --check-redis
```

`--check` 检查技能、本地配置、知识块、索引和图，不联网；`--check-redis` 连接 Redis，不调用模型。这些检查不能证明云服务可用，也不能证明模型以后总会遵从技能。

先关闭技能，再启用技能，对照同一个完整问题：

```powershell
uv run python lesson08a.py --skill none --session compare "根据笔记解释贴现是什么，再计算票面金额10000元、年贴现率3%、剩余90天的贴现利息，按一年360天计算。"
uv run python lesson08a.py --skill bank-study --session compare "根据笔记解释贴现是什么，再计算票面金额10000元、年贴现率3%、剩余90天的贴现利息，按一年360天计算。"
```

两次都沿用 7.2 的基础规则，都应查笔记并调用计算器，利息为 `75.00 元`。`none` 只是不追加技能说明，不会关闭工具或知识库。

启用 `bank-study` 后，观察回答是否更接近“白话解释、计算结果、条件提醒”的组织方式。用户指定格式时以用户要求为先，模型输出不保证逐字固定，也可能本来就接近这种结构。

会话按“技能名 + 会话编号”隔离，因此两次虽然都叫 `compare`，历史互不污染。8.1 使用独立的 Redis 前缀，已有课程记录仍保留，旧笔记和向量继续复用。

本课每条命令只问一次；不填问题时，会运行上面的默认贴现例子，**不会进入交互模式**。不写 `--skill` 默认使用 `bank-study`，不写 `--session` 默认使用 `study`。

## 3. 追问与查看历史

```powershell
uv run python lesson08a.py --skill bank-study --session compare "其他条件不变，改成180天，利息是多少？"
uv run python lesson08a.py --skill bank-study --session compare --history
uv run python lesson08a.py --skill none --session compare --history
```

追问要保持相同技能和会话编号，才能接上对应历史。补全条件后，本轮只需调用计算器，利息为 `150.00 元`；技能不会要求每轮都重新解释概念或查笔记。两条 `--history` 只读各自历史，不调用模型。

## 4. 代码怎样把说明交给模型

外层仍是 `prepare → agent → remember`。`SkillChatModel` 给 7.2 的模型包了一层：`prepare` 调用普通 `invoke()` 时原样转交，保持问题补全流程；工具模型经过 `bind_tools()` 后，内层调用才追加技能说明。

技能正文补充到内层已有的 system 消息后面，保留基础规则和用户要求，不增加新工具。仅把文件放进目录不会自动生效，必须有程序读取并把正文放入模型请求。

先看 `lesson08a_skills.py` 的三处：

| 代码 | 作用 |
| --- | --- |
| `load_skill()` | 读取选中的 `SKILL.md`，校验并拆出元信息与正文 |
| `add_skill()` | 保留基础 system 内容，追加所选技能的方法说明 |
| `SkillChatModel` | 普通调用照旧代理，工具绑定后才启用技能包装 |

你可以修改项目中 `skills/bank-study/SKILL.md` 的正文，例如要求解释更简短。保存后，下次启动程序会重新读取；不需要重建现有 24 个笔记向量，因为变的是工作方法，不是笔记内容。

本课只是 `SKILL.md` 的最小加载器，不会执行 Markdown 里的代码或脚本。更复杂的技能可以带 `scripts`、`references`、`assets`，但需要程序支持读取或执行，本课不需要创建这些空目录。

2. 修改技能说明后，是否需要重建笔记向量？为什么？
