## 2. 谁决定，谁执行

```text
启动 MCP Server → 握手 → list_tools → 包装工具 → bind_tools
                                                    ↓
用户问题 → Qwen → 有 tool_calls → ToolNode → MCP 客户端发送请求
              ↑                                     ↓
              └── ToolMessage ← 返回结果 ← Server 执行计算
              ↓
          最终回答 → END
```

没有工具调用时，Qwen 可以直接回答。`list_tools()` 返回工具名称、用途和参数说明；`StructuredTool` 把这些说明和客户端调用函数包装成 LangChain 工具，`bind_tools()` 再把工具说明交给模型。

**`bind_tools()` 不执行计算，模型返回 `tool_calls` 时也还没计算。** 模型只是提出“调用哪个工具、传什么参数”。

| 角色 | 本课负责什么 |
| --- | --- |
| Qwen | 提出工具调用；拿到结果后组织回答 |
| LangGraph 的 `ToolNode` | 执行模型请求的客户端代理工具，将结果组成 `ToolMessage` |
| MCP 客户端与服务端 | 按 MCP 协议传递工具说明、调用请求和结果 |
| Server 中的计算器函数 | 真正执行利息计算 |

`ToolMessage` 带有对应的 `tool_call_id`，让模型知道“这个结果是在回答刚才哪一次工具调用”。模型才能把结果接回对话。

工具参数被拒绝、连接失败或超时时，本轮会停止；程序不会把报错当作计算结果继续作答。

先看 `lesson09b_mcp.py`：工具如何被发现、包装，以及客户端怎样调用 `call_tool()`。

再看 `lesson09b.py`：`model → tools → model` 怎样连成图，以及模型没有工具请求时怎样结束。

MCP 的 `async with` 连接范围要覆盖整轮图执行，工具调用结束后再关闭连接。`await` 表示等待异步操作完成；`ainvoke()` 是异步执行图或模型的方法，适合等待网络和子进程通信，不代表增加了另一个模型。
