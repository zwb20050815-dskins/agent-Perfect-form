# 第四课 · 4.3：让模型重新挑选资料

**RRF 看两路排名；Rerank 模型读取问题和候选文字，重新判断相关程度。**

```text
两路各最多取 5 个 → RRF 最多留 6 个 → 重排模型打分 → 最多取 3 个
                                                               ↓
                                                       可选交给 Qwen3 回答
```

先多留几个，是为了让重排模型有机会把原来排在第四、第五的好资料提上来。它只能在收到的候选中挑选，不能补回前面完全没找到的内容。

`--check` 只检查本地。真实检索会调用一次问题 Embedding 和一次 Rerank；重排会把问题、候选标题和正文发送给配置的服务，按其规则计费。笔记向量继续复用。

## 2. 接着生成回答

```powershell
uv run python lesson04c.py "借贷合计相等，就能确认没有写反方向或用错科目吗？" --answer
```

加上 `--answer`，会再调用一次 Qwen3 聊天模型，根据最终的资料回答并标注来源。这里应说明“不能”，并引用“会计分录 & 试算平衡”片段。

每次运行都是一次独立问答。排名不一定会变化；重排也不保证每次都更准确，仍要核对原文。相关性分数不是答案正确率，本课先不设“低于多少就丢弃”的阈值。

## 三种模型各做什么

| 模型 | 输入 | 输出 |
| --- | --- | --- |
| Embedding | 问题文字 | 问题向量，用来检索 |
| Rerank | 问题 + 候选标题与原文 | 每个候选的相关性分数 |
| Qwen3 聊天模型 | 问题 + 最后选出的原文 | 带引用的回答 |

RRF 是算法，不是第四种模型。

## 代码先看两处

- `rerank_candidates()`：发送问题和候选文字，请模型打分。
- `map_rerank_results()`：用返回的 `index` 找回对应知识块，再按模型分数排序。

API 的 `index` 从 0 开始，指“提交名单中的第几个”。例如返回 `index=4`，就是提交的第 5 块。不能把响应和候选直接按行拼在一起，否则可能把得分配给错误的原文。

答案中的 `[1]`、`[2]` 则根据最后选出的资料重新编号，和 API 的 `index` 是两回事。接口失败或结果不完整时，程序会明确报错。

WeKnora 可看 [rerank.go](https://github.com/Tencent/WeKnora/blob/bccb4b151bae403508da77fbb174efc79dc47c1a/internal/reranking/rerank.go) 的 `Rerank()`。本课保留“候选交给模型打分，再选前三条”；完整项目还包括阈值过滤、综合评分、MMR 等处理。
