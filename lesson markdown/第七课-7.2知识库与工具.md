观察日志中的 `search_notes` 和 `calculate_discount_interest`。解释应依据本轮检索原文，并使用形如 `[银行会计重点笔记:0022]` 的稳定引用；计算结果应来自计算器。


## 3. 两层图各管什么

```text
外层：START → prepare → agent → remember → END
内层（agent 节点内）：
START → model
model 有工具请求 → tools → model
model 无工具请求 → END，交回本轮回答
```

外层的 `prepare` 利用最近历史补全问题，`agent` 完成本轮工具调用，`remember` 留下最近 **3 轮**已完成的问答。外层图用 `RedisSaver` 保存状态，`Redis` 客户端负责连接和通信。

内层每轮都从新的 `messages` 开始：模型通过 `bind_tools` 看到两个工具，用 `tool_calls` 提出请求，`ToolNode` 执行 Python 函数，再把结果交回模型。一次请求可以包含两个工具。

历史用于理解“其他条件不变”这样的追问，**不作为本轮知识回答的证据**。本轮若继续解释笔记知识，就需要重新调用 `search_notes`；本轮若只改天数计算，就使用补全后的参数调用计算器。

`search_notes` 内部仍是熟悉的流程：`向量检索 + BM25 → RRF 合并取前 6 → rerank 取前 3 → 按默认 0.5 阈值过滤`。模型选择什么时候查，Python 执行这套检索流程。

工具返回原文和稳定资料编号。程序会检查回答引用的编号是否来自本轮结果；编号合法仍不等于原文支持结论，阅读时也要核对内容。没有通过筛选的资料时，会说明资料不足。

## 4. 查看历史和切换会话

```powershell
uv run python lesson07b.py --session study --history
uv run python lesson07b.py --session other --history
uv run python lesson07b.py --session study
```

`--history` 只读取 Redis 历史，不调用模型。`other` 使用另一份会话记录；如果尚未提问，应显示 0 轮。最后一条命令没有问题参数，会进入连续对话。

交互模式里输入 `/history` 查看当前历史，输入 `/session other` 切换会话，输入 `/quit` 退出。

7.2 的 Redis 会话前缀是 `knowledge-agent:lesson07b:v1:`。它与 6.2 分开，因此 6.2 中的 `study` 记录不会自动迁移到本课。

最近 3 轮指业务状态中的 `history` 长度，不表示自动删除全部旧 checkpoint。Redis 负责会话状态；知识块和向量索引仍保存在原来的本地文件中。

## 5. 代码先看四处

| 位置 | 先理解什么 |
| --- | --- |
| `lesson07b.py` 的 `prepare()`、`build_graph()` | 外层怎样补全问题、执行本轮任务、记住问答 |
| `lesson07b_tools.py` 的 `lookup_notes()`、`make_tools()` | 怎样把已有检索流程包装成 `search_notes` 工具 |
| `lesson07b_tools.py` 的 `run_agent()`、`build_tool_graph()` | 怎样绑定工具、创建本轮消息，并用条件边循环执行 |
| `lesson07b_tools.py` 的 `collect_answer()` | 怎样收集本轮来源、核对引用，并处理资料不足 |

阅读时先顺着一次完整问题走，不必一次记住所有参数。日志中的“模型请求”表示模型选择了工具；出现工具结果后，才说明 Python 已经执行。

当前配置已验证“查笔记＋计算得到75.00元”和“新进程恢复历史后只计算得到150.00元”。补全问题和工具选择仍由模型完成，要核对日志；遇到不完整请求，程序会停止该轮，不能把它当作已经成功执行。
