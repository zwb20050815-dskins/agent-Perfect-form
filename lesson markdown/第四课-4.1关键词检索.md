# 第四课 · 4.1：按关键词找资料

第四课分三步：**关键词检索 → 合并两路结果 → Rerank 重排**。本节先学关键词检索。

## 为什么再加一种检索

| 方法 | 主要看什么 | 常见用途 |
| --- | --- | --- |
| 向量检索 | 文字的意思是否接近 | 同义词、换个说法提问 |
| 关键词检索 | 有没有匹配的词语 | 专业术语、名称、编号 |

例如查“补充登记法”，明确的术语就是很好的线索。两种方法各有长处，哪种效果更好，要用实际问题比较。

本节用 **jieba** 把中文拆成词，再用 **BM25** 排序：匹配到问题里的词通常加分；越少见的词通常越有区分度；重复次数和片段长度也会影响分数。不用先背公式。

## 运行

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
uv sync
uv run python lesson04a.py --check
uv run python lesson04a.py "补充登记法适用于什么情况？"
```

`uv sync` 会安装本节新增的 `jieba`、`rank-bm25` 及其依赖。装好后，脚本完全在本地运行，不需要 API Key，也不调用 Embedding 或聊天模型。

先看“问题分词”，再看排在前面的原文。应能找到“科目、方向正确但金额写少了，应补记差额”的说明，来自 `银行会计重点笔记:0016`。

为了看清流程，这个小实验每次运行都会在本地读取 24 个块、分词和统计词频。它不会重新生成或修改第三课的向量；资料多了以后再保存、复用关键词索引。

## 换两个问题

```powershell
uv run python lesson04a.py "贴现利息"
uv run python lesson04a.py "现金流量表"
```

应分别找到贴现利息公式、三大财务报表。然后试一个笔记里没有的词：

```powershell
uv run python lesson04a.py "zzzxqv987654"
```

这次应提示没有关键词匹配，不会随便列出三个零分片段。没有字面匹配，不代表一定没有意思相关的资料。

想比较两种方法，可以对同一个问题分别运行：

```powershell
uv run python lesson04a.py "想看公司这一年赚了多少，应该看哪张报表？"
uv run python lesson03b.py search "想看公司这一年赚了多少，应该看哪张报表？"
```

比较哪些知识块排在前面；不要直接比较两种方法的分数大小。第二条仍会调用问题 Embedding API。

## 代码先看三处

| 代码 | 作用 |
| --- | --- |
| `tokenize()` | 把问题和知识块拆成词 |
| `BM25Okapi(corpus)` | 根据所有知识块，统计哪些词常见、哪些词少见 |
| `get_scores(query_words)` | 给每个知识块打分，再取排名靠前的匹配块 |

标题和正文都参与检索。输出仍是笔记原文；下一小节才把关键词结果与向量结果合并。

WeKnora 中可先看 [keywords_vector_hybrid_indexer.go](https://github.com/Tencent/WeKnora/blob/bccb4b151bae403508da77fbb174efc79dc47c1a/internal/application/service/retriever/keywords_vector_hybrid_indexer.go) 的 `Retrieve()`，认识统一的检索入口。本课用 Python BM25 做小实验；WeKnora 的 PostgreSQL 方案使用 ParadeDB 提供关键词检索，pgvector 本身不提供 BM25。
