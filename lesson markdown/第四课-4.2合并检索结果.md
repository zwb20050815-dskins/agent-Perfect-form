# 第四课 · 4.2：合并两路检索结果

现在有两种找资料的方法：向量检索看意思，BM25 看词语。本节让它们各找一批，再合成一份结果。

```text
                  ┌ 向量检索：前 5 个候选 ┐
用户问题 ────────┤                      ├→ RRF 合并、去重 → 前 3 个知识块
                  └ BM25 检索：前 5 个候选 ┘
```

本节仍先看检索结果。下一小节再学习 Rerank 重排。

## 为什么不能直接加分

向量相似度可能是 `0.8`，BM25 分数可能是 `12`。两种分数不是同一把尺，直接相加会让数值较大的一路占优势。

**RRF 看每个块在各路的名次，再把名次换成贡献相加。** 本例两路权重相同：

```text
某一路的贡献 = 1 ÷ (60 + 该路名次)
融合得分 = 向量这一路的贡献 + BM25 这一路的贡献
```

排名越靠前，贡献越大；没进入某一路候选，就没有那一路的贡献。两路都找到了同一个块，会贡献两次，但结果只保留一条。这里按 `chunk_id` 判断是不是同一个块。

60 是本例选用的平滑参数，不是结果数量。先理解“用排名计分”，不用急着调它。

## 1. 看一个不联网的例子

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
uv run python lesson04b.py --demo
```

这是人工设定的排名，和你的真实笔记无关：

| 知识块 | 向量名次 | BM25 名次 |
| --- | --- | --- |
| A | 1 | 3 |
| B | 2 | 1 |
| C | 3 | 没进入候选 |
| D | 没进入候选 | 2 |

B 的得分是 `1/62 + 1/61`，A 的得分是 `1/61 + 1/63`。因此融合后 B 排在 A 前面。最终前三名是 **B、A、D**。

## 2. 用你的笔记检索

```powershell
uv run python lesson04b.py --check
uv run python lesson04b.py "补充登记法适用于什么情况？"
```

沿用原来的配置与依赖。你会看到两份候选排名，以及融合后的名次、分数、来源和原文。应能找到“错账更正三方法”中的说明。

真实检索会调用一次问题 Embedding API；笔记向量继续复用，BM25 和 RRF 在本地计算。本节不调用聊天模型或重排模型。

表格中的 `—` 只表示没进入该路取出的前几个候选，不代表这一路在全部资料中完全找不到这个块。

再换个问题观察：

```powershell
uv run python lesson04b.py "想看公司这一年赚了多少，应该看哪张报表？"
```

两个数量分开理解：`--candidates 5` 是每一路最多取 5 个；`--top-k 3` 是合并后最多留下 3 个。先取较多候选，是为了给后面的筛选留余地。

RRF 只使用两路排名，并不会重新阅读原文判断能否回答。融合不保证每个问题都更准确；原来没找到的内容也不会凭空出现。仍然要核对最后选出的原文。

## 代码先看三处

| 函数 | 作用 |
| --- | --- |
| `vector_search()` | 复用第三课的向量检索 |
| `keyword_search()` | 复用 4.1 的 BM25 检索 |
| `rrf_fuse()` | 按块编号合并，累加两路的排名贡献，再排序 |

RRF 是一个算法，不需要新的模型。WeKnora 中对应 [knowledgebase_search_fusion.go](https://github.com/Tencent/WeKnora/blob/bccb4b151bae403508da77fbb174efc79dc47c1a/internal/application/service/knowledgebase_search_fusion.go) 的 `fuseWithRRF()`。它还支持权重和分数归一化；本节先用等权的原始 RRF 分数学习。
