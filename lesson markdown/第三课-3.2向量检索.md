# 第三课 · 3.2：按意思找到笔记

这一步输入问题，找出最相关的 3 个知识块。下一步才让 Qwen3 根据这些资料回答。

## 先理解流程

```text
建索引：知识块的标题 + 正文 → Embedding 模型 → 向量 → 存到本地
提问题：问题 → 同一个 Embedding 模型 → 向量 → 比较相似度 → 取前 3 块
```

**向量就是一串数字，用来比较文字的意思是否接近。** 比如“公司这一年赚了多少”和“利润表”，用词不同，也可能匹配。

两种模型各有分工：

| 配置 | 做什么 |
| --- | --- |
| `CHAT_MODEL=qwen3.8-flash` | 根据文字生成回答，本步用不到 |
| `EMBEDDING_MODEL=qwen3.7-text-embedding` | 把文字变成向量，本步使用 |

Embedding 沿用 `.env` 中的聊天服务地址和密钥。以上是你当前服务已验证的模型 ID；更换服务时要重新确认。笔记和问题必须用同一套 Embedding 配置。

## 运行三条命令

先进入项目：

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
```

**1. 本地检查：**

```powershell
uv run python lesson03b.py --check
```

只检查配置和切块文件，不联网。通过不代表 API 一定可用。

**2. 建立索引：**

```powershell
uv run python lesson03b.py index
```

示例的 24 块已在准备本课时建好索引，所以你可能看到“已复用”。索引保存在 `data/vectors/银行会计重点笔记.vectors.json`，每条记录保留原文、标题、来源和 1024 个向量数字。

建索引会把知识块的标题和正文发送给配置的服务，按服务商规则计费。内容和配置不变时复用本地文件；改变笔记、重新切块或更换模型后，再运行 `index` 更新。需要强制重建时用 `index --rebuild`。

**3. 提问检索：**

```powershell
uv run python lesson03b.py search "资产类账户增加时，应该记借方还是贷方？"
```

程序只把问题发送给 Embedding 服务，再在本地比较向量。应能找到“各类账户增减方向”表格。终端展示的是笔记原文，还不是模型生成的答案。

相似度分数用于排序，**不是答案正确率**。即使知识库没有答案，程序也会列出最接近的片段，需要看内容是否真的有关。图片目前只检索链接和文字说明，没有识别图片里的内容。

## 代码先看三处

| 函数 | 作用 |
| --- | --- |
| `embedding_text()` | 拼接标题和正文 |
| `build_index()` | 调用 `embed_documents()`，把知识块向量存下来 |
| `search()` | 调用 `embed_query()`，按余弦相似度排序 |

余弦相似度比较两个向量的方向是否接近。先理解“越相关越靠前”，不用先背公式。其余代码主要负责读配置、检查文件和复用索引。

本课用 JSON 存储、逐块比较，适合这 24 块的小实验。后面再换成 PostgreSQL + pgvector；混合检索、MMR、Rerank 也在后续学习。

想对照 WeKnora 源码时，先看 [embedding/protocol.go](https://github.com/Tencent/WeKnora/blob/bccb4b151bae403508da77fbb174efc79dc47c1a/internal/models/embedding/protocol.go) 中的 `Embed()` 和 `BatchEmbed()`：分别处理一段文字和多段文字。本课学相同思路，用 Python 实现。
