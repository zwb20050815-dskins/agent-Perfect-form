# 第三课 · 3.3：让 Qwen3 根据笔记回答

上一小节找到资料。这一小节把“问题 + 资料”交给 Qwen3，生成带来源的回答。

```text
问题 → Embedding → 检索前 3 个知识块
                           ↓
                   问题 + 知识块原文
                           ↓
                       Qwen3 回答
```

笔记向量继续复用。聊天模型收到的是文字，不是那 1024 个数字。

## 1. 检查

在 PowerShell 运行：

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
uv run python lesson03c.py --check
```

沿用现有 `.env`，不用新增配置或依赖。`--check` 检查两种模型的配置、知识块和索引，不调用云 API。

如果提示缺少索引或索引已过期，先运行 `uv run python lesson03b.py index`。

## 2. 让模型回答

```powershell
uv run python lesson03c.py "试算平衡能发现所有记账错误吗？"
```

你应该看到一段整理后的回答，说明“不能发现所有错误”，并用 `[1]` 这样的编号标注依据。编号对应下面列出的文件、章节和知识块。

每次提问会调用一次问题 Embedding，再调用一次聊天模型。问题和检索到的原文会发送给你配置的服务，按服务商规则计费。

## 3. 对照原文

```powershell
uv run python lesson03c.py "资产和负债增加，分别记借方还是贷方？" --show-context
```

检查回答是否说清“资产增加记借方，负债增加记贷方”，并确认引用对应“各类账户增减方向”表格。

再问一个这些会计资料没有提供数据的问题：

```powershell
uv run python lesson03c.py "中国银行2025年的净利润是多少亿元？"
```

期望回复：**当前检索到的资料不足以回答这个问题。** 不应该凭模型记忆补数字，也不能据此断言整个知识库都没有答案。

来源清单列出的是本次交给模型的全部片段，不代表每一条都被答案引用。程序会检查引用编号是否存在；结论是否真有依据，仍要对照原文。这是一个最小 RAG 示例，提示词不能保证模型永远不出错。

## 代码先看这三句

```python
results = search(index, question, embedding_model, top_k)
messages = build_messages(question, results)
response = chat_model.invoke(messages)
```

这是主流程的简写，分别表示：**找资料 → 组织问题和资料 → 调用聊天模型**。

`SYSTEM_PROMPT` 是回答规则，要求模型只根据资料回答、标注来源、资料不足时说明。`build_messages()` 负责给片段编号，再把问题和资料放进消息里。笔记中的指令只是资料内容，不是程序的规则。

想对照 WeKnora 时，看 [into_chat_message.go](https://github.com/Tencent/WeKnora/blob/bccb4b151bae403508da77fbb174efc79dc47c1a/internal/application/service/chat_pipeline/into_chat_message.go) 如何把检索结果组织成带编号的上下文，不必现在读完整个文件。
