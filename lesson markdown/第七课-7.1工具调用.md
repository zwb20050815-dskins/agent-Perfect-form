## 3. 数据怎么走

```text
用户问题
  ↓
Qwen3：请求 calculate_discount_interest，给出票面金额、年贴现率、天数
  ↓
Python：校验参数 → 执行计算器 → 返回 75.00 元
  ↓
Qwen3：读取工具结果 → 组织最终回答
```

第一遍模型返回的 `tool_calls` 是调用请求，里面有工具名、参数和编号，**这时尚未执行计算**。

`ToolNode` 执行对应的 Python 函数，把结果装成 `ToolMessage`。其中的 `tool_call_id` 对应请求编号，方便模型知道结果属于哪次调用。

计算示例通常调用模型两次；普通问候通常一次就够了。若模型提出进一步工具请求，图可以再循环，本课最多调用模型 3 次。

## 4. 代码先看四处

打开 `lesson07a.py`：

| 代码 | 作用 |
| --- | --- |
| `@tool` 与 `calculate_discount_interest()` | 把 Python 函数包装成工具，提供名称、说明和参数格式 |
| `model.bind_tools(TOOLS)` | 告诉模型有哪些工具可选；这里不会执行工具 |
| `ToolNode(TOOLS)` | 根据模型请求校验参数，并真正执行工具 |
| `tools_condition` | 有工具请求就走 tools 节点，否则结束 |

图中 `tools → model` 的边，把工具结果再次交给模型。

发给模型的是工具的名称、用途和参数格式；Python 函数保留在本地，由程序执行。

本课 State 的 `messages` 使用 `MessagesState` 自带的合并规则：新编号的消息追加到列表，相同编号的消息更新原消息。**它和之前普通字段“新值覆盖旧值”的规则不同。** `model_calls` 仍按普通字段处理。

`DiscountInput` 规定参数范围。例如 `annual_rate_percent=3` 表示 3%，`days` 必须是整数。参数校验可以检查格式和范围，但不能替你判断模型是否理解了用户意思，所以也要观察日志中的参数。

## 5. 和你想做的 Agent 有什么关系

你之前的算命 API，也可以包进一个工具函数：模型给参数，Python 函数请求网站，再把网站结果返回模型。本节先用本地计算器理解同一套流程。

本课每次命令都是一次独立提问；它不读取笔记，也不连接 Redis。因此这里没有知识库来源引用。下一小节再学习把“查笔记”和“执行工具”放进一个 Agent。
