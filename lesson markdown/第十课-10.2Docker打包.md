# 第十课 · 10.2：用 Docker 运行知识 Agent

这节把已有 API、Python 和依赖装进镜像，再启动容器。**仍然调用云端模型，不是在容器里安装 Qwen。** 现有笔记向量可以继续用。

## 1. 先理解三个词

| 名称 | 可以理解为 |
| --- | --- |
| `Dockerfile` | 制作运行环境的配方 |
| 镜像（image） | 按配方做好的代码和运行环境 |
| 容器（container） | 镜像启动后的运行实例 |

`compose.api.yaml` 负责说明 API 怎样启动、使用哪些文件、怎样连接 Redis；`.dockerignore` 决定哪些文件不进入构建材料。

镜像不包含密钥、笔记和 Skill。容器运行时，通过**只读挂载**读取 E 盘项目的 `.env`、知识块、向量和 `skills`。历史仍保存在原来的 Redis 数据卷中。

## 2. 安装并启动

先打开 Docker Desktop，等引擎运行。在自己的 PowerShell 执行：

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
uv run python 'C:\Users\Zwb\Documents\Codex\2026-10-06\n-h-2\outputs\knowledge-agent\install_lesson10b.py'
docker compose -f compose.redis.yaml -f compose.api.yaml config --quiet
```

最后一条命令没有输出、正常结束，表示 Compose 配置格式通过。然后构建并启动：

```powershell
docker compose -f compose.redis.yaml -f compose.api.yaml up -d --build --wait --wait-timeout 180
```

第一次需要下载基础镜像、安装锁定版本的依赖，可能较慢。`--build` 构建镜像，`-d` 在后台运行，`--wait` 等待服务就绪。

这两份配置合用，会沿用原来的 Redis 服务和数据卷。不要另外启动一个使用同一数据卷的 Redis。

启动后，再检查容器内的配置、知识索引、Redis 和 MCP：

```powershell
docker compose -f compose.redis.yaml -f compose.api.yaml exec -T api python lesson10a.py --check
Invoke-RestMethod 'http://127.0.0.1:8001/health'
```

`--check` 不调用云端模型，也不计算利息。健康接口成功后，再用真实问答验证完整流程。

## 3. 先问一次，再重启 API 追问

打开 [容器里的接口测试页面](http://127.0.0.1:8001/docs)，展开 `POST /chat`，点击 **Try it out**，填写：

```json
{
  "session_id": "docker-study",
  "question": "根据笔记解释贴现是什么，再计算票面金额10000元、年贴现率3%、剩余90天的贴现利息，按一年360天计算。"
}
```

点击 **Execute**。预期得到带来源的解释和 **75.00 元**利息；`used_tools` 可以看到本轮使用的工具。

等回答完成，再回到 PowerShell 重启 API：

```powershell
docker compose -f compose.redis.yaml -f compose.api.yaml restart api
```

稍等片刻，刷新页面，使用相同会话编号追问：

```json
{
  "session_id": "docker-study",
  "question": "其他条件不变，改成180天，利息是多少？"
}
```

预期得到 **150.00 元**。API 进程已经重启，但历史保存在 Redis，仍可补齐金额、利率等条件。

这一轮可以只调用计算器，`sources` 为空也正常。也可查看 [这段会话的历史](http://127.0.0.1:8001/sessions/docker-study/history)。

## 4. 为什么有三个地址？

| 地址 | 谁使用、表示什么 |
| --- | --- |
| `127.0.0.1:8001` | Windows 浏览器访问容器 API 的入口 |
| `0.0.0.0:8000` | API 在容器内部监听的地址 |
| `redis:6379` | API 容器通过服务名访问 Redis 容器 |

因此，容器里的 `REDIS_URL` 是 `redis://redis:6379/0`。Compose 已设置好，不需要改 Windows 本地使用的 `.env`。

**在 API 容器里，`127.0.0.1` 指 API 容器自己。** 写成 `127.0.0.1:6380`，就找不到另一个容器里的 Redis。

本课使用 Windows 的 **8001**，避免和上一节的 **8000** 冲突。端口只绑定本机 `127.0.0.1`；现在还没有部署到公网。

## 5. 代码和数据分别放在哪里？

```text
Windows 浏览器 → 本机 8001 → API 容器内 8000
                              ├─ LangGraph / 本地检索
                              ├─ MCP 计算器子进程
                              ├─ 读取只读挂载的配置、笔记和 Skill
                              └─ Redis 容器 → 原来的持久化数据卷
```

MCP 计算器是 API 容器里的一个子进程，本课不用为它再开一个容器。模型仍通过网络调用云端 API。

只读挂载让容器读取 E 盘现有文件；Redis 数据卷保存历史。只重启或重建 API 容器，不会清除 Redis 中的历史。Redis 自身重启后的恢复，还依赖原来配置的 AOF 和保留的数据卷。

## 6. 停止与排错

本课结束时，只停止 API：

```powershell
docker compose -f compose.redis.yaml -f compose.api.yaml stop api
```

出错时，先查看状态和最近日志：

```powershell
docker compose -f compose.redis.yaml -f compose.api.yaml ps
docker compose -f compose.redis.yaml -f compose.api.yaml logs --tail 60 api
```

反馈问题时提供错误类别和相关日志，不要发送 `.env` 或密钥。镜像下载失败先检查 Docker Desktop 的网络配置，不要随意更换陌生镜像站。若 `/docs` 空白，可用上一节的 PowerShell 请求示例，把端口改成 `8001`。

本次执行环境无法连接 Docker 控制管道，因此容器构建、启动和这两轮问答，需要在你的 PowerShell 完成实际验证。
