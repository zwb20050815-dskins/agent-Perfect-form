# 第三课 · 3.1：把长笔记分成知识块

第三课分三步：**切块 → 向量化与检索 → 让 Qwen3 根据检索结果回答**。现在只做切块，不调用模型。

## 为什么要切块

问“资产负债表反映什么”时，通常只需要相关的一小段。把整本笔记都发给模型，会增加上下文长度和费用，也容易混入无关信息。

切块就是把长笔记整理成多个小片段。之后检索时找到有关的片段，再交给模型。

## 这次怎么切

1. 识别标题，记录当前章节。
2. 按空行划分段落，把相邻段落合在一起。
3. 遇到新标题，或再加一段会超过约 600 个字符时，保存当前块。
4. 表格保持完整；单段或表格超过 600 字符时，允许这一块超长。

如果一个标题本身包含说明，却没有后续正文，也会把它保留下来。

600 是本课的起始目标，不是最优参数，也不是 token 数。标题变化会提前结束一个块，所以很多块会更短。这一版先不增加块之间的重复内容。

## 运行

在 PowerShell 执行：

```powershell
Set-Location -LiteralPath 'E:\agent Perfect form\knowledge-agent'
uv run python lesson03a.py
```

脚本只用 Python 自带模块，无需安装新包。默认读取第二课生成的会计笔记 `.md` 和同名 `.json`，结果保存到：

```text
data/chunks/银行会计重点笔记.chunks.json
```

当前样本按默认参数应生成 **24 个块**。原笔记内容变动后，数量也可能变化；每次运行会更新这份切块结果。

## 看懂一个块

打开生成的 JSON，会看到一个列表，其中每个对象是一块资料：

| 字段 | 含义 |
| --- | --- |
| `chunk_id` | 文件名加块编号，便于在本课中找到某一块 |
| `source_file`、`source_path` | 原 HTML 的文件名与位置 |
| `heading_path` | 这一块属于哪个标题、哪个小节 |
| `text` | 这一块的正文 |
| `char_count` | 正文的字符数 |

标题单独记录在 `heading_path`。后面生成向量时，会把标题与正文一起使用，让模型知道片段在讲什么。

## 一个小实验

把目标长度改为 200，结果放到另一个目录，方便比较：

```powershell
uv run python lesson03a.py --chunk-size 200 --output data/chunks_200
```

比较两次结果：块数有没有变化？哪些段落被拆到不同块？表格是否仍完整？超出目标长度的完整表格是预期行为。

要切其他笔记，继续使用熟悉的 `--source`：

```powershell
uv run python lesson03a.py --source 'data/markdown/银行经济学重点笔记.md'
```

## 本步完成标准

- 找到“各类账户增减方向”表格，确认六类账户仍在同一个块里。
- 能通过一个块的来源字段，指出它来自哪份笔记、哪个章节。
- 理解：块太大可能带入无关内容，块太小可能丢失必要上下文。

代码的核心在 `split_markdown()`：`headings` 记录章节，`paragraphs` 收集段落，`save_chunk()` 保存一个块。先读懂这三个部分。

本版适用于第二课生成的三份普通 Markdown 笔记；复杂代码块、跨页表格等情况以后再处理。
